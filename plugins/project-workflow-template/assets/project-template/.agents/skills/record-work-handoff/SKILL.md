# 팀 작업 인계

1. 프로젝트 루트의 `AGENTS.md`와 `SOT/SourceOfTruth.md`를 확인한다. 요청에서 프로젝트, 작업 ID, 담당, 담당 `WNN`, 기존 현황표 행을 확인한다. `T01` 같은 작업 ID는 프로젝트별로 유지하고 시트의 `(프로젝트, 작업 ID)`로 같은 행을 식별한다. `WNN` 하나에 작업 여러 건이 있을 수 있다. 일치하는 기존 행이 여러 개거나 기존 행 값을 확인할 수 없으면, 해당 행에 붙일 완성 TSV를 만들기 전에 사람에게 확인한다.
2. 오늘 한 일과 관련된 원본 및 작업 파일만 연다. 파일 경로와 확인한 위치를 남기고 날짜·기한·담당·승인·송부 상태가 미확인 또는 충돌이면 그대로 표시한다. 작업본 생성, 실제 검증, 담당자 검토, 공식 승인·송부는 각각 확인한 범위로 기록한다.
3. 담당 `WNN`의 기존 작업 기록에 작업 ID별 인계를 갱신한다. 알맞은 기록이 없으면 해당 `WNN`의 `HANDOFF.md`에 남긴다. `원본(경로·위치) → 방법(적용한 절차·가정) → 산출물(경로·버전) → 검증(대조 결과·미확인) → 다음 행동(담당·기한 또는 다음 확인 시각)`을 짧게 연결한다. 날짜별 사본은 만들지 않는다. 아직 `WNN`이 없는 작업은 확인한 정보로 행을 준비하되 검증되지 않은 파일 경로는 비워 둔다.
4. 확인된 행의 현재 값을 바탕으로 이번 작업에서 근거가 생긴 셀만 갱신한다. 새 행은 해당 프로젝트에 없는 새 작업임을 확인한 경우에만 준비한다. 아래 순서대로 **헤더 없이 한 물리적 줄**을 `tsv` 코드 블록에 넣는다. 실제 탭 7개로 8열을 유지하고 셀 내부 탭·줄바꿈은 공백으로 바꾼다. 미확인 근거 경로는 빈 열로 유지한다. 필요하면 코드 블록 밖에 확인할 사항을 한 줄로 적는다.

| 프로젝트 | 작업 ID | 담당 | 다음 행동 | 기한·확정 여부 | 상태 | 최근 한 일 | 근거 파일 경로 |
|---|---|---|---|---|---|---|---|

근거 파일 경로는 팀원이 공유 프로젝트 루트에서 찾을 수 있는 프로젝트 상대 경로를 쓴다. 상세 내용은 `WNN` 기록에 두고 `최근 한 일`은 확인한 변경 한 문장으로 쓴다. 담당자가 방금 갱신된 값과 대상 행을 확인하고 직접 붙여넣는다. 시트 구조가 위 열 순서와 다르거나 입력 범위에 수식이 있으면 붙여넣기 전에 해당 입력 셀을 확인한다.

공식 상태 변경 후보와 근거는 담당 `WNN`에서 통합자에게 인계한다. `SOT/REVIEW`와 공식 SOT는 지정된 통합자 및 `update-project-sot`의 사람 승인 절차를 따른다.

## 횡하중–층간변위각 작업 예시

- **원본** — 시험 기록에서 시편, 가력 순서, 횡하중 채널과 단위를 확인한다. 계측도에서 상대변위 계산에 쓸 두 기준점과 기준거리를 확인한다. 가력기 변위를 직접 사용하는지는 계측 정의로 판단한다.
- **방법** — 두 기준점 상대변위를 기준거리로 나눈 뒤 100을 곱해 층간변위각(%)으로 표시한다. 영점과 부호 처리, 단위 변환, 채널 동기화, 제외 구간을 작업 기록에 적는다. 가력 순서를 살려 가로축 층간변위각, 세로축 횡하중으로 그린다.
- **산출물** — 변환표, 검토용 그래프와 보고서에 넣을 그림의 해당 파일 또는 위치를 연결한다.
- **검증** — 한 스텝의 원시 채널 값을 변환표와 그래프의 점까지 대조한다. 위 예시에서 기준거리를 아직 확인하지 못했다면 그 대조가 끝났다고 쓰지 않고 `검증 대기`를 남긴다.
- **다음 행동** — 계측도를 확인해 기준거리와 변위 채널을 확정한 뒤 원시 값부터 그래프까지 대조한다. 확인하지 않은 숫자나 파일명을 예시에서 옮겨 쓰지 않는다.
